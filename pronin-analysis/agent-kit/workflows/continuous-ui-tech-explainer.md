рендерятся в 60 fps. Не переносить «N кадров» из референса без пересчёта (G28).

## 1. Назначение и контракт

Русское вертикальное видео-объяснение технической идеи через один непрерывный интерфейсный
холст: тёмная сетка с маской, короткие строчные фразы, живой UI и предметы, которые показывают
существительные и глаголы, blur-переходы, объекты-мосты, движущаяся камера. Панели и окна —
только когда они играют роль в действии, не как рамка для контента. Это интерпретация
задокументированных приёмов, не копия чужого проекта.

Суть формата одной строкой: **голос говорит — на экране крупный объект делает именно это, и
ничего лишнего.**

Для обратного отсчёта/рейтинга, ведущего в кадре или чистого screen-демо — другие workflow.
Движок: HyperFrames в `projects/hyperframes/<slug>/`; Remotion для этого формата не создавать.

- 1080×1920, 60 fps, русский, 35–55 с (длину определяет измеренный голос, G11).
- Один вопрос → один ответ. Каждый факт имеет источник в `media/research.md`; заявления
  компаний подписаны как заявления, демо — как демо, статистика платформы — как статистика.
- **Никаких бегущих субтитров.** 1–5 смысловых слов за раз. Существительное → объект/элемент UI,
  глагол → действие. Word-тайминги Deepgram запускают события, а не транскрипт.
- Единая визуальная система (§3). Не копировать логотипы, аватар, CTA или экраны референса.
- Голос Fish Audio; транскрипция Deepgram по **финальному локальному файлу**; музыка и SFX —
  Epidemic Sound (выбор пользователя для этого формата перекрывает общий дефолт). SFX только
  на видимые события. Все ассеты локально до сборки; источник и права записаны.

## 2. Принятые настройки этой серии

Использовать без повторного запроса; новое указание пользователя имеет приоритет.
Это настройки только этой серии, не всех форматов.

- HyperFrames; 1080×1920, **60 fps**.
- Fish Audio, `voice_id=48ec28a45588422b977a86460c11977f` («Энергичный Рассказчик»).
  Проверять доступность и возвращённый ID; не менять голос молча. Модель — только та,
  что реально есть в схеме подключения; не обещать «последнюю».
- Произношение (только в TTS-тексте, U12): `AI` → «эй-ай», `IT` → «айти». На экране всегда

  shadcn → «шад-си-эн», B2B SaaS → «бэ-ту-бэ саас», Claude Code → «клод код»).
  Не подменять AI на «ИИ».
- Палитра: фон `#111` с сеткой точек, текст белый / `#8C8C8C`, **один** акцент стиля (синий)
  на активном элементе (U06). Натуральные цвета реальных логотипов и узнаваемых иконок
  допустимы.
- Формат, канал и CTA — общие настройки владельца из `AGENTS.md` → «Channel defaults»:
  Instagram Reels 9:16 1080×1920; канал `milanko.ai`, логотип **`assets/logos/milanko.ai/logo.jpg`**
  (не генерировать и не заменять; старый `jev-explainer/assets/channel-avatar.jpg` не использовать);
  CTA-подписка в конце **каждого** ролика.
- В этом формате CTA делается механикой P7 (§5). Рубрика на экране: «что это такое?» +
  «разбираю каждый день».
- Текстовый shimmer: только внутри букв, спокойный проход ≈1.5 с.
- Компании, предметы и сюжет Jev не являются шаблоном для нового ролика.

## 3. Инварианты стиля — проверять в каждой сцене

| № | Инвариант | Типичное нарушение |
|---|---|---|
| I1 | **Сцена — это действия, а не слайд.** Каждая сцена = 3–4 события по 1.5–3 с, привязанных к словам голоса. | Готовая композиция стоит 7–10 с; все элементы появились разом. |
| I2 | **Соседние сцены различаются механикой** (§5). Одна механика — не более одного раза подряд. | Два дерева выбора подряд (B02 и Kintsugi в Jev). |
| I3 | **Главный герой виден с первой секунды** и получает акцент на первом упоминании в голосе. Статистика визуально привязана к герою. | Голос говорит «Jev», на экране только логотип Vercel и число. |
| I4 | **2–5 смысловых слов на экране, ≤4 элемента (U01, U02).** Нет ярлыков-рубрик, номеров в углу, чипов-категорий, подписей-дублей голоса, футеров, прогресс-баров, фейковых дашбордов, сносок-источников (они в `media/post-description.md`). Заголовки обычными словами, без формул «X → Y» (U04). | Слайд «SaaS skills · 05/10 · чип · заголовок · окно · подпись · футер». |
| I5 | **Типографика (U03):** строчные, вес 600; главный текст — то, что запоминают (название, герой, цифра), 88–120 px, одна строка с автоподбором; пояснение 44–48 px `#8C8C8C`; UI и код ≥28 px; ничего <27 px. Нет «синей второй строки». | Название инструмента мелкой серой строкой внизу, а крупно — второстепенная фраза. |
| I6 | **Композиция (U05):** центр x = 540, поля 64 px; главный текст ≈ y 300–480, центр объекта ≈ y 900–1100, объект 70–80% ширины. Зоны Reels (низ ~320, право ~170 px) — без смысла, но не рамка центрирования. | Всё мелкое в середине, половина кадра пустая; группа сдвинута влево. |
| I7 | **Нет пустых кадров.** Каждый кадр ролика содержит смысловой контент; кадр, где виден только фон или только курсор, — дефект. | Пустой кадр между Browser Use и выводом. |
| I8 | **Нет жёстких появлений.** Каждый новый смысловой элемент имеет вход; каждая смена сцены — перекрытие или общий объект (§7). | Схема Kintsugi возникла целиком в один кадр. |
| I9 | **Нет инертных холдов > 1 с.** Держать сцену действием (набор, выбор, счёт, камера, последовательное раскрытие); idle-float — только полировка. | Финал и CTA стоят статично 4 с. |
| I10 | **Контекст сохраняется:** заголовок уезжает в шапку, введённый запрос уменьшается и остаётся, от него строится связь к результату; сквозной объект переезжает между сценами. | Каждый бит очищает экран. |
| I11 | **Роли участников однозначны:** ввод — каретка, решение модели — перебор/подсветка, клик — курсор. У каждого участника своя метка, движущаяся с ним. | Курсор «выбирает» за модель; подписи «текст: другая модель». |
| I12 | **Перебор ≠ решение:** перебор — обводка/свечение; решение — заливка акцентом, выскок 1→1.08→1, галочка. Альтернативы остаются приглушёнными (opacity .25, blur 2 px). | Одинаковая синяя заливка при переборе и выборе; альтернативы удалены. |
| I13 | **Не выдумывать данные:** никаких «уверенность 82%», фиктивных метрик компаний. Иллюстративный UI отмечать в `media/post-description.md`. | Пустая иконка «уверенность». |
| I14 | **Предмет только как метафора:** ≤1 предмет на сцену, ≤4 на ролик, по правилам §6. Предмет без понятной роли — удалить. | Чаша кинцуги висит в углу и закрывает схему. |
| I15 | **Сироты запрещены:** после удаления/замены элемента не остаются его рамки, плашки, плитки и пустые места (G27). | Пустая серая плашка после зачёркнутого ответа; одинокая плитка «выбор». |
| I16 | **Голос ведёт (U10, U11):** сцены длятся столько, сколько фраза; событие за 0.1–0.15 с до слова, не раньше чем за 1 с; под речью кадр меняется ≤ 1.5 с. | Пауза 3 с после каждой фразы; схема показана за 6 с до того, как о ней сказали. |
| I17 | **Акцент на активном (U06):** в каждый момент выделено то, о чём говорит голос; один акцентный цвет. | Весь ролик серый; или синий, зелёный и фиолетовый одновременно. |
| I18 | **Свой объект у каждого пункта (U08):** общая схема объясняет устройство, но не держит на себе весь ролик. | 10 скиллов показаны мелкими чипами на одной схеме. |

## 4. Драматургия ролика (скелет)

### 4.1 Хук — общее для всех вариантов (U09)

Первая реплика понятна **сама по себе**. Два допустимых типа:
- **Прямая тема + польза:** «Делаем мультиагентную систему из Claude Code или Codex»,
  «Как Vercel выбирает модель за тебя». Предпочтителен для практических роликов.
- **Парадокс / цифра + герой:** «Модель, которая не пишет ответы, за сутки подключили 13% команд».

Запрещено: фразы-загадки и метафоры, которым нужна следующая фраза («Один Claude Code — один
разработчик»), и их экранные формулы («один → команда»). Экран: к 1.0 с герой/тема показаны
крупно; кадр на 2.5 с без звука объясняет, о чём ролик.

### 4.2 Вариант «вопрос → ответ» (объяснение одной технологии)

| Блок | Время | Задача | Обязательно |
|---|---|---|---|
| Хук | 0–3 с | Тема или парадокс/цифра + герой | Герой в центре с 1-й секунды (I3); цифра показана **относительно** (сетка из 100 точек, доля, сравнение), а не голым числом; предмет-каламбур допустим. |
| Вопрос | 3–10 с | «зачем?/как?» | Крупная короткая формулировка; герой остаётся в кадре и переезжает в следующую сцену. |
| Механизм | ~10–16 с | Как это работает | Одна механика §5, показывающая суть (ввод → решение). |
| Примеры | 2–3 × 5–7 с | Доказательства | **Разные механики** (I2); у каждого примера один главный результат и время на его прочтение (§8). |
| Вывод | 5–8 с | Ответ на вопрос | Примеры сходятся в общий вывод (P6), честное ограничение. |
| CTA | 3–5 с | Подписка | P7, длина по реальной реплике (G11). |

Сценарий строится вокруг одного вопроса (G04). Самая цепляющая мысль — в первые 2 с.
Если текущий текст прячет парадокс в конец фразы — предложить пользователю перестановку
до озвучки (озвученный и принятый текст без согласования не менять).

### 4.3 Вариант «набор инструментов» (N скиллов / сервисов / шагов в этом стиле)

| Блок | Время | Задача | Обязательно |
|---|---|---|---|
| Хук | 0–3 с | Прямая тема + польза (4.1) | Тема крупно наверху обычными словами; показан сам инструмент (терминал, окно продукта). |
| Устройство (опц.) | 4–8 с | Как всё связано | Одна схема (P4), элементы появляются на своих словах; дальше схема **уходит** или становится мостом в первый пункт. |
| Пункты | N × 3.5–5 с | Каждый пункт | Механика P9: главный текст = название пункта, пояснение 2–4 слова, свой объект с действием. Соседние пункты — разные объекты и действия (I2, I18). |
| Вывод / ограничение | 3–5 с | Честная оговорка | «скиллы не заменяют тесты» и т.п. — крупно, одним объектом. |
| Справочный экран (опц.) | 5–7 с | Команды / ссылки | Механика P10, холд ≥ 3 с на слове «паузу». |
| CTA | по реплике | Подписка | P7. |

Порядок пунктов — порядок реальной работы (до кода → код → проверка), а не случайный.
Кому/где применяется пункт — говорит голос; на экране это видно по позиции/акценту, а не чипом.

## 5. Каталог сценических механик

Выбирать механику под смысл реплики. Соседние сцены — разные механики (I2).
Подробные раскадровки — в `reference/videos/`.

| ID | Механика | Когда | Анатомия (события) | Ловушки |
|---|---|---|---|---|
| P1 | **Герой + относительная статистика** | Хук с цифрой | сетка точек волной → на имени героя pop плашки героя в центре → N точек загораются акцентом и тянут линии к герою → над сеткой счётчик 0→N% → pill-источник снизу | Голое число без героя; источник крупнее героя. |
| P2 | **Ввод → решение** | «как это работает» | заголовок в центре → уезжает вверх → поле ввода, набор по буквам → курсор отправляет и сразу уходит → поле уменьшается под заголовок → линия к узлу модели → варианты со stagger → перебор (обводка, замедление) → решение (заливка, галочка) → итоговая строка под вариантами | Курсор выбирает за модель; удаление альтернатив; пустой кадр между шагами. |
| P3 | **Отбор → измеримый результат** | «ускорили поиск», «сократили» | стопка карточек быстро тасуется (≤1.5 с) → остаются отобранные → они уменьшаются и поднимаются, **не исчезают** → под ними прибор/сравнение: исходное состояние ≥1.2 с → изменение → результат держится до конца фразы | Тасовка 3 с, а результат мелькает 0.5 с. |
| P4 | **Причинная схема** | маршрутизация, выбор в два шага | узел «запрос» → линия рисуется вниз → варианты уровня 1 со stagger → решение → следующая ветка дорисовывается → решение 2; при длинной схеме — камера едет вниз по пунктиру с motion blur | Пустой пунктирный каркас заранее; схема целиком в один кадр; повтор P2. |
| P5 | **Живой интерфейс с актёрами** | демо агента/браузера | окно UI → каретка с меткой «другая модель» печатает → курсор с меткой героя кликает → UI реагирует (результаты, состояние) → курсор сразу уходит | Роли объяснены мелкими подписями; курсор паркуется. |
| P6 | **Схождение в вывод** | итог | логотипы/иконки показанных примеров влетают с разных сторон (stagger) → сходятся к центральной оси → морф в плашку-вывод → ограничение («варианты задаёшь ты», «проверяй на своей задаче») | Проходной объект без смысла сбоку; центр группы ≠ центр плашки. |
| P7 | **CTA-карточка канала** (обязательна в каждом ролике) | конец | прошлый экран уезжает вверх с blur → рубрика «что это такое?» → карточка (логотип `assets/logos/milanko.ai/logo.jpg`, название `milanko.ai`, обещание ≥27 px) → курсор кликает «подписаться» → морф в «вы подписаны ✓» → спокойный float до последнего кадра | Статичный хвост; мелкое обещание; блик по прямоугольнику. |
| P8 | **Текстовая трансформация** | «минуты → секунды», «не пишет ответы» | исходное слово читается ≥1.2 с → зачёркивание/скотч/маска → морф в новое слово → чтение ≥0.8 с | Изменение раньше, чем прочитали исходное. |
| P9 | **Карточка пункта** (скилл, сервис, шаг) | каждый пункт варианта 4.3 | счётчик «3 / 10» (36 px, серый) меняет цифру (старая вверх, новая снизу, 0.3 с) → главный текст = название (U03) стирается и печатается → пояснение 2–4 слова кроссфейдом → крупный объект показывает **действие пункта** по цепочке «исходное → действие → результат» (U07) на словах голоса → результат держится до конца фразы | Название мелко внизу; объект — картинка результата без действия; одинаковый объект у соседних пунктов; фейковые данные. |
| P10 | **Живой справочный терминал** | команды установки, ссылки | окно на всю ширину (поля 48–64 px), mono 28–32 px, 60–70% высоты → команды печатаются (≈0.012 с/символ), после каждой «✓» и имя белым → ≤ 3 с на всё → финальный кадр неподвижен ≥ 3 с, значок ⏸ пульсирует один раз на слове «паузу» | Стена мелкого текста; непроверенные команды или лишние аргументы; холд < 3 с. |

Примеры объектов P9 (действие, а не иллюстрация): вопросы появляются и получают ответы
(уточнение требований); чек-лист «план · код · проверка» с галочками на словах; «client» и
«customer» съезжаются в одно слово (общие термины); дерево папок раскрывается; три одинаковые
проверки съезжаются в одну функцию, от которой линии к трём местам использования; пипетка
трижды берёт пробу со скриншота-каркаса и из каждой точки вылетает правило (цвет, шрифт,
радиус); мигающие рамки перерисовок гаснут; скан проходит по блокам и загораются замки.

Новую механику можно добавить, если она объясняет реплику лучше; после проверки внести её сюда.

## 6. Предметы (стикеры)

Стиль референса — **не** иконки и не эмодзи. Два допустимых типа:
- **Предметная фотосъёмка:** реальный предмет, настоящие материалы, натуральный цвет.
- **Простой однотонный 3D:** одна простая форма, один натуральный цвет, минимум деталей.

Правила:
- Предмет — **визуальный каламбур** к фразе (золотой унитаз = «всё г…но», балаклава = «без лица»,
  золотая рама = «задаёшь рамки», скотч на слове = «не пишет ответы»). Если роль предмета надо
  объяснять — он не нужен.
- ≤1 на сцену, ≤4 на ролик. UI-сцены (P2, P4, P5) обычно без предмета.
- Натуральный цвет предмета; **никакой перекраски в фирменный цвет**, неона, LED, болтиков,
  «роботизации». Предмет — единственное насыщенное пятно в монохромном кадре.
- Запрещено: маскоты-роботы, библиотеки 3D-эмодзи (Fluent и т.п.) как замена предметам,
  грязные/ржавые фактуры рядом с чистыми студийными.
- Функциональность (G14): отверстия прозрачны (внутренность рамы), движущиеся части
  отдельными слоями или SVG (стрелки прибора — SVG поверх пустого циферблата), края без ореола
  на белом и чёрном фоне, мягкая тень `drop-shadow(0 24px 40px rgba(0,0,0,.55))`.
- Процесс: сгенерировать серию → контактная сетка на `#111` → самопроверка по списку выше →
  показать сетку → встраивать. Удалённый пользователем предмет не возвращать без прямого указания.

Промпт (реалистичный):
```
Studio product photograph of a real [OBJECT], single isolated object, true-to-life materials
and natural colors, soft key light from top-left, subtle reflections, sharp focus, 3/4 view,
pure black background, minimal, no text, no glow, no neon, no LEDs, no added decorations,
no robot parts, no stylization, photorealistic, 1024x1024
```
Промпт (однотонный 3D):
```
Simple 3D render of a [OBJECT], one solid natural color, smooth glossy clay material, soft studio
lighting, very simple rounded shape, minimal details, 3/4 view, pure black background, no text,
no glow, no extra parts, 1024x1024
```

## 7. Переходы

Каждая граница сцен описывается в `media/scene-plan.md` четырьмя полями:
**исходящее** (что и как уходит) · **сохраняемое** (общий объект/шапка) · **входящее** (порядок входов) ·
**перекрытие** (интервал, когда оба живы).

- Уход начинается ≈0.1–0.2 с **до** слова-триггера; входящая сцена уже смонтирована (clip ranges перекрываются).
- Базовая схема (U13): уход blur 0→12 px + opacity 1→0 + scale 1→0.96 за 0.3 с; вход обратный
  за 0.3–0.4 с, стартует через 0.15 с после начала ухода. Новый текст не становится резким,
  пока старый ещё читается.
- **Сначала искать объект-мост:** какой элемент уходящей сцены может стать элементом новой
  (слово → папка, файл → строки кода, ответы → пункт чек-листа, узел схемы → поле ввода,
  собранные блоки → карточки). Если моста нет — базовая схема, а в `scene-plan.md` пометка
  «мост не найден».
- Смена текста на месте — стирание и печать (0.025–0.03 с/символ) или blur-кроссфейд;
  ширина контейнера анимируется вместе с текстом. Мгновенная замена текста запрещена.
- Общая шапка/логотип/счётчик меняется на месте через blur-out/blur-in, не двигается.
- Сквозной объект (герой) перемещается пружиной, всё время видим, без дубля.
- Смена темы/«мира» (тёмный → светлый) — через серый или диагональную шторку, со смыслом.
- Запрещено: fade в пустой экран; одновременная полная замена всего содержимого; проходной
  объект без роли в аргументе (I15).

## 8. Тайминг и чтение

- **Время задаёт голос (U10).** Длительность сцены = её фраза + пауза 0.25–0.4 с. Если анимации
  не хватает времени — упростить анимацию или согласовать изменение текста, но не растягивать
  тишину и не резать речь.
- Событие стартует за 0.1–0.15 с до слова-триггера и **не раньше чем за 1 с** (U11). Пока звучит
  голос, кадр меняется не реже раза в 1.5 с; первые 0–1.5 с ролика — тоже (печать, раскрытие).
- Событие = вход → действие → **чтение результата** → уход. Чтение — отдельный интервал.
- Минимумы: исходное состояние сравнения ≥1.2 с; результат после снятия маски ≥0.8–1 с;
  главный результат сцены держится до конца своей фразы.
- Разгонные анимации (тасовка, перебор) ≤1.5 с — время отдаётся выводу.
- Уход сцены начинается за 0.1–0.2 с до первого слова следующей.
- Ритм: 2–3 визуальных события в секунду в активных фазах, новый «экран» каждые ≈2–3 с.

## 9. Параметры движения (секунды; справочно кадры @60 fps)

Референс измерен при 30 fps: «8 кадров» референса = 0.27 с = 16 кадров @60.

| Действие | Параметры | @60 fps | Что проверить |
|---|---|---|---|
| Вход слова/объекта | blur 10→0, opacity 0→1, y 10→0 (объект: scale 0.4→1.08→1) | 0.2–0.27 с = 12–16 кадров | Старт на смысловом слове. |
| Пружина переезда | spring без overshoot | 0.4–0.5 с = 24–30 кадров | Объект всё время видим. |
| Уход группы | y −60 px, blur 0→10, fade | 0.33 с = 20 кадров; старт за 0.2 с до слова | Контейнер жив до конца ухода. |
| Замена логотипа в шапке | blur-out / blur-in | по 0.27 с = 16 кадров | Центр не прыгает. |
| Рисование линии | stroke-dashoffset, нормализованный pathLength | 0.27–0.33 с = 16–20 кадров | Нет вспышки линии до анимации. |
| Stagger вариантов | — | 0.1 с = 6 кадров | Каждый узел со своим входом. |
| Схождение источников | spring, stagger | 0.13 с между источниками | Центры совпадают. |
| Быстрый оборот стрелки | 360°, ease-in-out, SVG-стрелка | 0.33 с = 20 кадров | Нет запечённой стрелки в PNG. |
| Уход курсора после клика | сразу после действия | 0.2–0.27 с = 12–16 кадров | Кончик попал в цель после reflow. |
| Тасовка карточек | 3D-наклон, перекрытие | ≤1.5 с всего | Итоговые карточки читаемы отдельно. |
| Idle-float | translateY ±3 px, rotate ±1° | цикл ≈3 с | Детерминированно, до последнего кадра. |
| Текстовый shimmer | background-clip:text | проход ≈1.5 с | Только внутри букв. |

## 10. Этапы и согласования

1. **Исследование и бриф.** Первичные источники; один вопрос; takeaway; claims в `media/research.md`; выбор workflow в `media/workflow.json`.
2. **Стиль (один раз на серию).** Инвентаризация `assets/`, `projects/hyperframes/_shared/`, Storybook. `assets/styles/continuous-ui-tech/DESIGN.md` + board `Styles/continuous-ui-tech/Reference`. Согласование стиля.
3. **Сценарий.** Скелет §4 (выбрать вариант 4.2 или 4.3); хук по 4.1; честное ограничение; CTA-реплика серии (§2). Чистый `media/script.md` + точный `media/tts-script.txt` (эмоции, ударения, словарь произношений, U12). Создать `media/spec.md` — единую актуальную спецификацию ролика (U16). **Явное согласование именно этой версии** (G01). До него — никаких вызовов Fish/Deepgram/Epidemic.
4. **Голос и тайминг (U10).** Короткий preflight → генерация по абзацам → проверка полноты каждой фразы (G09) → нарезка только по пословным тайм-кодам (−0.08 / +0.15 с, fade 10 мс), паузы 0.25–0.4 с → сборка → Deepgram по финальному файлу → `media/transcript/captions.json` — единственный источник времени. Таблица сверки фраз в `media/voice/QA.md`.
5. **План сцен — `media/scene-plan.md` (обязательно до кода).** Для каждой сцены: главный текст и пояснение (обычными словами, U04), механика §5, объект и его действие (U07), предмет (если есть и зачем), таблица «событие | слово-триггер | время (с) | чтение до», переход по полям §7 с объектом-мостом. Самопроверка плана по §3 (I1–I4, I14, I16–I18). Затем `media/beatmap.json` с постоянными ID. **Согласование плана.**
6. **Пилот из трёх фрагментов** (MP4 со звуком, 1080×1920): хук (0–5 с), самая сложная сцена, один переход с мостом. Режиссёрская самопроверка §11 по MP4, включая просмотр на ширине 360 px. Показать пользователю, дождаться отзыва. Решения пилота записать в `media/spec.md` как шаблон для всех сцен.
7. **Полная сборка.** Масштабировать принятый шаблон на все сцены. Одна master timeline HyperFrames, детерминированно, локальные медиа. `hyperframes check`.
8. **Режиссёрская самопроверка §11 + технический QA (production-qa)** по закодированному MP4. Исправить всё найденное **до** показа.
9. **Звук и финальный рендер.** Epidemic музыка/SFX, SFX на видимые события, уровни по голосовым окнам. ffprobe: 1080×1920, 60 fps, H.264/AAC, длительность. `videos/<timestamp>-<slug>/<slug>.mp4`.

При недоступности провайдера — остановить зависимый этап, сообщить операцию и ошибку, не менять провайдера молча.

## 11. Режиссёрская самопроверка (перед каждым показом)

Технические проверки не доказывают качество (G29). Перед отправкой любого MP4 — тестового
или финального — пройти этот список **по закодированному файлу**.

Как смотреть:
```bash
# контактные листы: 2 кадра/с, 8×2 плитки = 8 с на лист
ffmpeg -i out.mp4 -vf "fps=2,scale=200:-2,tile=8x2:padding=4:color=gray" -q:v 3 qa/sheet_%02d.jpg
# плотная раскадровка каждого перехода: 10 кадров/с, 1.2 с вокруг границы
ffmpeg -ss <t-0.6> -t 1.2 -i out.mp4 -vf "fps=10,scale=240:-2,tile=6x2" qa/seam_<id>.jpg
# полноразмерные кадры для замера кеглей и зоны y
ffmpeg -ss <t> -i out.mp4 -frames:v 1 qa/full_<t>.jpg
```
Сверить word-тайминги из `captions.json` с моментами событий на листах.

| Вопрос | Проходит, если |
|---|---|
| Это слайд? | В каждой сцене ≥3 события; нигде финальная композиция не стоит > 1 с без действия (I1, I9). ≤4 элементов, нет хрома и заглушек (I4, U02). |
| Соседние сцены похожи? | Механики и объекты соседних сцен различаются (I2, I18). |
| Хук понятен? | Первая фраза понятна без второй; кадр на 2.5 с без звука объясняет тему (4.1, U09). |
| Герой виден сразу? | В кадре 0–1 с и на первом упоминании в голосе — герой в центре (I3). |
| Сколько текста? | Нигде > 5 смысловых слов; заголовки обычными словами, без «X → Y» (I4, U04). |
| Читается на телефоне? | Кадр, уменьшенный до 360 px: главный текст читается первым; два самых длинных названия — в одну строку или корректный перенос (I5, U03). |
| Центр и поля? | Центр главной группы x = 540 ± 8 px; поля симметричны (I6, U05). |
| Однотонно или пёстро? | Каждый кадр имеет выделенный активный элемент; один акцентный цвет (I17, U06). |
| Картинка и голос вместе? | Каждое событие не раньше чем за 1 с до своего слова; под речью нет статики > 1.5 с; нет пауз > 0.4 с между фразами (I16). |
| Голос целый? | Первое и последнее слово каждого клипа целые, нет чужих звуков на краях; таблица сверки в `media/voice/QA.md` (U10). |
| Есть пустой кадр? | Ни одной плитки листа без смыслового контента (I7). |
| Есть жёсткие появления/склейки? | На seam-листах 10 fps каждый элемент входит, сцены перекрываются, текст не меняется за один кадр (I8, U13). |
| Клики звучат? | На каждом клике в сведённом MP4 слышен SFX (U14). |
| Справочный экран читается? | Команды проверены, ≥28 px, финальный кадр неподвижен ≥3 с (P10). |
| Роли понятны без звука? | Кто вводит, кто решает, кто кликает — видно по каретке/подсветке/курсору и их меткам (I11, I12). |
| Успевают прочитать результат? | Главный результат каждой сцены виден ≥0.8–1.2 с (§8). |
| Предметы работают? | Каждый предмет — каламбур к своей фразе; убрать его = потерять смысл (I14). |
| Есть сироты? | Нет пустых плашек, одиноких плиток, остатков удалённых элементов (I15). |
| Все правки раунда выполнены? | Каждая строка `media/change-log.md` отмечена и проверена по кадру; `media/spec.md` отражает последнюю правку, старые решения из неё удалены (G25, G41, U16). |
| CTA на месте и живой? | Последняя сцена — подписка на `milanko.ai` с логотипом из `assets/logos/milanko.ai/logo.jpg`; реплика звучит целиком; клик → смена состояния → движение до последнего кадра; обещание читается (P7). |
| Формат Reels? | ffprobe: 1080×1920 (9:16); смысловой контент вне нижней ~300 px и правой ~170 px зоны интерфейса Instagram. |

Если хоть один пункт не проходит — исправить и пройти список заново. В сообщении пользователю
кратко перечислить, что проверено — отдельно техническую, визуальную и речевую проверку со
своими доказательствами (G42), — и какие правки раунда внесены (со ссылками на время в ролике).
Невыполненный пункт раунда назвать прямо.

## 12. Технические уроки (сохранять)

- **Fish Audio.** MCP `text_to_speech` принимает `voice_id`; `reference_id` игнорируется и может списать
  кредиты за дефолтный голос. Селектора модели в проверенной схеме не было — проверять живую схему
  при каждой настройке; не называть модель без доказательства. После просьбы пользователя прекратить
  исследование провайдера — прекратить (G07).
- **Длинные TTS-вызовы** могут «проглотить» целое предложение при валидном MP3 (так пропала фраза
  про Kintsugi). Генерировать по абзацам, сверять Deepgram с каждой согласованной фразой, чинить
  только плохой фрагмент, склеивать по измеренной тишине. Логировать task_id, кредиты, отклонённые
  дубли, склейки и хеш в `media/voice/QA.md`.
- **ASR — помощник, не прослушивание.** Deepgram искажает бренды (Jev, Vercel, Kintsugi, Browser Use);
  в визуале брать написание из сценария. Не заявлять о качестве звука без прослушивания.
- **Отклонённый голос обнуляет тайминги.** Держать ID битов и порядок; все триггеры пересчитать по
  новому голосу. Пока голос не принят — тайминги помечены «provisional» в Storybook.
- **Review-поверхность.** HyperFrames-снимки могут пройти, пока iframe Storybook ещё грузится —
  проверять живой Overview и каждый бит на их review-времени.
- **Master timeline.** Принятую сцену импортировать из production-кода, не перерисовывать. Вложенный
  GSAP context/timeline может выглядеть верно в снимках, но в MP4 отрендерить только дочерний — тогда
  сплющить селекторы и тайминги в master. Проверять декодированные кадры всех сцен; при расхождении
  fast capture и screenshot — отключить экспериментальный capture и перерендерить.
- **Логотипы.** Смотреть содержимое официального SVG: favicon может быть просто кругом, а полезный знак —
  в шапке сайта. Сохранять источник, проверять визуально.
- **Перекрытия.** Тасуемые карточки намеренно перекрываются — помечать как intentional overlap только
  затронутые текстовые блоки после осмотра, не всю сцену.
- **Превью.** Если в review-браузере нет H.264 — локальный WebM-фолбэк; основным артефактом остаётся
  проверенный H.264 MP4.
- **Владение свойствами.** У свойства элемента в интервале один владелец; при смене поведения удалять
  старое управление (G21, G22).

## 13. Переиспользование

Companion skill владеет canvas/panel-примитивами и проверенными компонентами механик §5. Расширять
только из реальной потребности. Storybook и production используют одни токены и одну реализацию экрана.

Принятый пример: `videos/2026-09-29-jev-ai-cta/jev-60fps.mp4`, код `projects/hyperframes/jev-explainer/`
(локальные артефакты). Брать принципы и проверенные части; не копировать цепочку поздних
переопределений как шаблон — при переносе объединить управление каждой сценой в одном месте.
