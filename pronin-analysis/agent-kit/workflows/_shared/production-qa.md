# Стандарт видео и обязательные проверки (все форматы)

Читать **целиком** перед каждым новым видео и перед каждым кругом правок, вместе с выбранным
workflow. Файл из трёх частей:

- **Часть A — «Видео, а не презентация».** Универсальные правила кадра, хука, голоса, монтажа
  и цвета (U01–U16). Действуют во **всех** форматах; workflow может ужесточить значения, но не
  отменить правило. Если `DESIGN.md` стиля противоречит части A (кегли, центр, обязательные
  панели) — побеждает часть A, а расхождение записать в `media/change-log.md`.
- **Часть B — регистр ошибок** (G01–G44): что уже шло не так и как это ловить.
- **Часть C — проверки по этапам**, которые выполняются до показа пользователю.

Пользовательские указания имеют приоритет. Синий цвет, тёмная сетка, отсутствие субтитров и
конкретный голос — настройки отдельных серий, **не** часть этого стандарта.

---

## Часть A. Видео, а не презентация

Главный тест любого кадра: **зритель без звука за 2 секунды понимает, о чём этот момент, и видит,
что что-то происходит.** Если кадр можно распечатать и он ничего не потеряет — это слайд.

### Кадр

**U01. Кадр = объект, совершающий действие.** Каждый экран строится вокруг одного крупного
объекта, который что-то делает (печатает, сливается, раскрывается, выбирает, проверяет).
Элементов на экране не больше четырёх: главный текст · короткое пояснение (опц.) · объект ·
служебный счётчик (опц., только если помогает структуре, например «3 / 10»).

**U02. Никакого презентационного хрома.** Запрещены без прямой просьбы пользователя:
- ярлыки-рубрики в углу («SaaS skills», «Шаг 2»), номера страниц «05/10» в углу, прогресс-бары
  внутри кадра, футер с названием канала (канал — только в CTA);
- чипы-категории, которые дублируют голос («backend + frontend»), подписи под объектом,
  пересказывающие голос;
- светофор и заголовок окна macOS, если окно не играет роли; карточка-подложка вокруг всего
  кадра («рамка в рамке»);
- фейковые данные-заглушки: дашборды «Revenue $12,840», графики, кнопки «+ New», проценты
  «уверенности»; градиенты и тени ради красоты; разноцветная подсветка синтаксиса.

Тест для каждого элемента: *если его убрать, пропадёт смысл?* Нет → удалить.

**U03. Иерархия: самый крупный текст — то, что зритель должен запомнить.** Название
инструмента, имя героя, ключевая цифра — главный текст экрана, а не служебная строка.
Размеры на кадре 1080×1920:

| Роль | Кегль | Правило |
|---|---|---|
| Главный текст | 88–120 px, Onest/гротеск 600 | Одна строка, автоподбор по ширине 952 px; минимум 60 px. Перенос (по дефису, ближе к середине) — только если не влезает в 60 px. |
| Пояснение | 44–48 px, серый | 2–4 слова. |
| Текст внутри UI/кода | ≥ 28–30 px | Моноширинный для кода и команд. |
| Абсолютный минимум | 27 px | Ничего мельче. |

Проверка: кадр из MP4, уменьшенный до ширины 360 px, — каждый главный текст читается сразу.
Отдельно проверить два самых длинных названия ролика.

**U04. Экранный текст — обычными словами.** Никаких формул-метафор «X → Y» («один → команда»,
«вопрос → ясность»), которые надо расшифровывать. Пояснение говорит, что происходит:
«уточняет требования», «стиль со скриншота». Тест: человек, не слышавший голос, понимает фразу.

**U05. Композиция по центру кадра.** Горизонтальный центр — x = 540. Поля симметричные, 64 px.
Зоны интерфейса Reels (нижние ~320 px, правые ~170 px, верхние ~120 px) — это **зоны
исключения** (туда не класть смысл), а не рамка, по которой центрировать группу. Объект сцены
занимает 70–80% ширины; главный текст ≈ y 300–480, центр объекта ≈ y 900–1100.

**U06. Цвет: нейтральная основа + один акцент на активном.** Акцент (один цвет стиля) всегда
показывает, где сейчас смысл: то, о чём говорит голос. Натуральные цвета реальных логотипов,
предметов и узнаваемых иконок (папки macOS и т.п.) допустимы. Дефекты: кадр без единого
выделенного элемента дольше 2 с («однотонно»); два и больше акцентных цветов («пёстро»).

**U07. Объект показывает причину, а не картинку результата.** Цепочка «исходное → действие →
результат» видна на экране, и результат физически вытекает из действия: плашка вылетает из
точки клика пипетки; три одинаковые строки съезжаются и сливаются в одну функцию, а не
исчезают; галочка ставится в момент слова. Исходное состояние держится ≥ 1.2 с до действия,
результат ≥ 1 с.

**U08. Разнообразие: у каждой смысловой единицы свой объект.** Каждый пункт списка / пример /
инструмент получает собственный крупный объект и свою механику. Общая схема или общий экран —
только для объяснения устройства (например, «оркестратор и два исполнителя»), а не контейнер
для всего ролика. Соседние сцены не повторяют механику.

### Хук

**U09. Хук понятен с первой фразы.** Первая реплика прямо называет тему и пользу простыми
словами («Делаем мультиагентную систему из Claude Code или Codex») **или** даёт парадокс/цифру,
привязанную к герою. Запрещено: маркетинговые фигуры и метафоры, которые требуют следующей
фразы для понимания («Один Claude Code — один разработчик»). Экран: к 1.0 с назван или показан
герой/тема; кадр на 2.5 с **без звука** объясняет, о чём ролик. Это проверяется отдельно.

### Голос и время

**U10. Голос ведёт, картинка подстраивается.** Порядок всегда такой: утверждённый текст →
голос → пословные тайм-коды (Deepgram) → длительности сцен выводятся из голоса → монтаж.
- Резать аудио **только в паузах между словами**: начало = start первого слова − 0.08 с, конец =
  end последнего + 0.15 с, fade 10 мс. Никогда не резать по длительности сцены, не ускорять речь.
- Паузы между фразами 0.25–0.4 с, между блоками ≤ 0.6 с. Пауза 3 с «пока доигрывает сцена» —
  дефект: сокращается сцена, а не удлиняется тишина.
- Каждый клип проверить: первое и последнее слово целые, нет чужого звука на краях.

**U11. Каждое событие привязано к слову.** Элемент появляется за 0.1–0.15 с до своего
слова-триггера; не раньше чем за 1 с (иначе картинка «обгоняет» голос). Пока звучит голос,
кадр меняется не реже чем раз в 1.5 с. В `media/scene-plan.md` — таблица «событие |
слово-триггер | время (с)».

**U12. Экранный текст ≠ текст для TTS.** На экране `AI`, `IT`, названия латиницей как в
оригинале; в TTS-тексте — транскрипция («эй-ай», «шад-си-эн», «бэ-ту-бэ саас»). Словарь
произношений ведётся до озвучки; сомнительные слова проверяются на коротком образце.

### Монтаж

**U13. Никаких мгновенных замен.** Ни один текст и ни один объект не меняется за один кадр.
- Смена текста на месте: стирание и печать (≈0.025–0.03 с/символ) или blur-кроссфейд 0.25 с
  с перекрытием; ширина контейнера анимируется вместе с текстом.
- Смена экрана: уход (blur 0→12 px, opacity 1→0, scale 1→0.96) 0.3 с; вход (обратный) 0.3–0.4 с;
  вход стартует через 0.15 с после начала ухода (перекрытие).
- Предпочтительно **объект-мост**: элемент уходящей сцены превращается в элемент новой
  (слово → папка, файл → строки кода, ответы → первый пункт чек-листа).
- Нет кадра, где на экране только фон, курсор или служебная строка. Новый текст не бывает
  резким, пока старый ещё читается.

**U14. Клик — одно событие.** Один тайм-код управляет касанием курсора, сменой состояния кнопки
и SFX. Курсор уходит сразу после действия.

**U15. Справочный экран (команды, ссылки, списки) — тоже сцена.** Только проверенные данные
(команды сверены с документацией, без лишних аргументов). Окно на всю ширину (поля 48–64 px),
моноширинный ≥ 28–30 px, по высоте 60–70% кадра; заполняется живо (печать, галочки, счётчик) за
≤ 3 с; финальный кадр неподвижен ≥ 3 с — это кадр для паузы.

### Правки

**U16. Правка — это цель, и она заменяет старое решение везде.**
- Все актуальные требования живут в одном файле `media/spec.md`. Новая правка **заменяет**
  противоречащую старую (например: «название наверху» отменяет «строка команды внизу»), а не
  добавляется рядом. Старые решения из прошлых версий не переносятся по инерции.
- Структурное замечание («похоже на слайды», «однотонно», «непонятно», «мелко») относится к
  шаблону сцены, а не к одному кадру: пересобрать шаблон и применить ко **всем** сценам.
- Каждый пункт раунда — строка в `media/change-log.md`; новая версия не отправляется, пока
  хоть одна строка текущего раунда не проверена по кадру MP4 (G25). Если пункт не сделан —
  прямо написать об этом в сообщении.
- Правка не отменяет правила части A (G26): выполнить смысл, сохранить правило, сообщить.

## Часть B. Регистр ошибок → правило → проверка
