## 0. Как пользоваться этим файлом

Порядок чтения: `production-qa.md` часть A → §0–§8 → **§F «Факты» (обязательна целиком)** →
§10. Приоритет при конфликте: указание пользователя → §F (факты) → инварианты §3 и U01–U16 →
§4–§5 → `assets/styles/quran-data-essay/DESIGN.md` → числа §9.
**Факт важнее красоты:** если сцена требует числа или цитаты, которые не прошли §F, сцену
убирают или меняют, а не «смягчают формулировку на глаз».
Все длительности в секундах; кадры только вместе с fps.

## 1. Назначение и контракт

- **Для:** коротких вертикальных эссе о тексте Корана, построенных на данных: подсчёты слов
  и корней, структура сур, порядок откровения, связи между стихами. Каждое утверждение
  показано как данные, которые зритель видит своими глазами (точки, счётчики, оси).
- **Не для:** проповеди, фетвы, толкования норм, «научные чудеса», сравнения религий,
  биографические ролики с изображением людей.
- **Суть одной фразой:** текст говорит — точки данных показывают это буквально, и каждое
  число можно пересчитать.
- Канал: **новый англоязычный канал** `<channel>` (имя и логотип — плейсхолдер, §2).
  Канальные дефолты milanko.ai из `AGENTS.md` (русский, CTA milanko.ai) **не применяются**.
- 1080×1920, 9:16, **60 fps**, английский текст на экране + арабский оригинал; длина 50–90 с
  (задаёт время чтения §8, не больше 110 с).
- **Без закадрового голоса и без субтитров.** Рассказ ведёт текст на экране; звук — эмбиент
  и SFX на видимые события (§9).
- Движок: HyperFrames (`projects/hyperframes/<slug>/`), частицы — canvas/WebGL внутри
  композиции, детерминированно (seeded), без случайности между рендерами.
- Не копировать из референса: имя «Frames of Noor/Quran», логотип-октаграмму, финальную
  карточку, формулировки. Брать приёмы, сетку, ритм, механики.

## 2. Принятые настройки этой серии

- Канал `<channel>`, логотип `assets/logos/<channel>/logo.svg`. Пока файла нет — финальная
  карточка рендерится только с текстовым плейсхолдером в превью; в публикуемый рендер без
  логотипа не идёт (сообщить пользователю).
- Финальная карточка: логотип + имя + строка методики (§F7) + «Follow for more», 3.0 с.
- Перевод смыслов: **Abdullah Yusuf Ali, 1934 (оригинальная редакция)** — один на весь канал.
  Источник файла и его лицензия записываются в `media/sources.md` до первого ролика (§F4).
- Арабский текст: **Tanzil, Uthmani, хафс** (зафиксированная версия файла, §F1).
- Морфология: **Quranic Arabic Corpus v0.4** (оригинал с corpus.quran.com) или форк
  `mustafa0x/quran-morphology` (sha256 `742bfac5…340645f`, проверен `count.py selftest`);
  какой именно — пишется в строке методики.
- Хадисы: только Sahih al-Bukhari и Sahih Muslim (§F5).
- Проверка человеком перед публикацией не требуется — вместо неё обязательны все
  автоматические проверки §F8; любой непройденный пункт блокирует рендер.

## 3. Инварианты стиля — проверять в каждой сцене

I1. **Фон** — один глобальный слой: радиальный градиент, центр (540, 900), R≈1150:
`#23365A` → `#0E1729` (70%) → `#050B13` (край); лёгкое зерно 2–3% и медленный дрейф
светового пятна ±20 px за 10 с от глобального времени. Проверка: средний цвет в точках
(20,20), (540,40), (20,960), (540,1880) совпадает во всех сценах ±2.

I2. **Палитра:** текст `#E2EAF4`; второстепенный `#8D9BB3`; акцент A — золото `#C9B072`;
акцент B — голубой `#8FA7D1`; сетка панели `#1C2A44`; точки «спят» `#3A4E72`, «горят» —
акцент сцены. Два акцента допустимы **только как две стороны сравнения** (A против B);
в сценах без сравнения — один акцент (золото). Красного, зелёного, неона нет.

I3. **Типографика:**
| Роль | Шрифт | Кегль @1080 | Прочее |
|---|---|---|---|
| Нарратив (1–2 строки) | Marcellus | 64–72 px | интерлиньяж 1.25, по центру, ≤ 38 символов в строке |
| Ключевое число / слово | Marcellus | 140–180 px | табличные цифры, «=» тем же кеглем |
| Арабский (стих) | Amiri Quran | 64–80 px | никогда не меньше 56 px |
| Перевод | Spectral Italic | 40–44 px | ключевое слово цветом акцента, как и в арабском |
| Транслитерация/глосса | Spectral Italic | 34–36 px | `#8D9BB3` |
| Ярлыки, ссылки (AN-NISA 4:82) | Inter SemiBold, капитель | 30–32 px | трекинг +12%, `#8D9BB3` или акцент |
Ни один текст меньше 30 px (референс использует 13–15 px — для Reels не годится).

I4. **Сетка кадра** (поля 72, контент 936):
- блок нарратива: верх y=300, ширина ≤ 900, по центру x=540;
- панель данных: квадрат 690×690, x 195–885, y 620–1310 (центр 540, 965);
  широкие объекты (ось времени, кольцевая схема) — ширина 900–936, центр y≈965;
- строка ссылки: y=1350 (под панелью), по центру;
- y > 1600 и правые 150 px — без смысла (зоны Reels);
- карточка стиха (без панели): арабский y≈700, перевод под ним через 32 px, ссылка через 24 px.
Проверка: `scripts/qa/layout-lint.js` (поля 72/1008) на кадре покоя каждой сцены → `[]`.

I5. **Точка = реальная единица данных.** Каждая точка на панели соответствует конкретному
стиху/слову; позиция детерминирована (сетка 79×79 для 6 236 стихов, порядок мусхафа
row-major, последние 5 ячеек пусты). Подсвеченные точки = ровно строки CSV вхождений
(§F3). Число на счётчике в каждый кадр = число горящих точек. Проверка: `verify_scene.py`
сверяет список подсвеченных индексов в сцене с CSV.

I6. **Священный текст:** арабский текст стиха появляется и уходит целиком (fade/blur
0.6–0.8 с, опционально построчно справа налево), никогда не рассыпается в частицы, не
отражается, не обрезается, не перекрывается другими элементами и не стоит на одном экране с
шутками/мемами. Частицами могут быть только точки данных и латинский нарратив.

I7. **Без людей и лиц**, без изображений пророков, мечетей-стоков, рук в молитве;
только данные, типографика, свет.

I8. **≤ 4 смысловых элемента в кадре** (нарратив, объект данных, ярлык, ссылка).

## 4. Драматургия (скелет)

### 4.1 Хук (0–3 с)
Одна фраза-обещание в Marcellus 64–72 px + сразу живой объект данных (вся сетка точек,
вспышка, ось). Примеры формы: «We counted every word of the Quran.», «This book was not
revealed in the order you read it.», «The longest surah is built like a mirror.»
Хук — утверждение, которое ролик **доказывает данными**, а не вопрос-кликбейт.

### 4.2 Скелет «подсчёт» (counts)
хук → «каждая точка — это …» (масштаб корпуса) → 2–4 пары/счёта, каждая: слово (арабский +
транслитерация + глосса) → подсветка вхождений → счётчик → (если пара) «A = B» → стих, где
слова стоят рядом → вывод-наблюдение → методика → финал.

### 4.3 Скелет «порядок/хронология» (order)
хук → корпус в порядке мусхафа → ось 610–632 CE → точки «падают» в порядке откровения →
примеры (первое/последнее откровение со ссылками) → перестановка в порядок мусхафа →
наблюдение → финал.

### 4.4 Скелет «структура» (structure)
хук → сура как полосы секций (по опубликованной схеме) → складывание по центру → пары
секций со стихами-близнецами (общее слово/корень подсвечено) → центр → наблюдение → финал.

### 4.5 Концовка
Последняя содержательная сцена — стих (карточка) как тихая точка. Затем финальная карточка
канала со строкой методики (§F7), 3.0 с, движение до последнего кадра.

## 5. Каталог сценических механик

Каждая: исходное → действие → результат; параметры в §9.

- **P1 Корпус-сетка.** Пусто → точки проявляются волной сверху вниз (1.2–1.6 с) → сетка
  79×79 «спящих» точек. Ярлык «each dot is one verse · 6,236».
- **P2 Поиск-подсветка.** Сетка спит → вхождения загораются по порядку текста (интервал
  ≥ 12 мс, весь проход 2–4 с) с лёгким всплеском частиц → счётчик рядом растёт синхронно.
- **P3 Сравнение A = B.** Два счётчика A (золото) и B (голубой) растут одновременно, каждый
  со своим набором горящих точек → на совпадении: «=» проявляется, кольцевая волна 1.0 с,
  тихий колокол. Если числа **не равны** — показываем как есть, без волны (§F2).
- **P4 Карточка стиха.** Панель гаснет до 15% → арабский целиком → перевод → ссылка;
  искомое слово подсвечено акцентом в арабском и в переводе одновременно.
- **P5 Ось времени.** Линия 610 CE → 632 CE (ширина 900), отметки Makkah/Hijra 622/Madinah;
  точки падают на ось в принятом порядке откровения (§F6) со световым следом.
- **P6 Перестановка.** Точки перелетают из одного порядка в другой (хронологический ↔
  мусхаф) по кривым, 2.0–3.0 с, с лёгким размытием в движении.
- **P7 Полосы-структура.** Секции суры как горизонтальные полосы A…E…A′ с подписями →
  складывание по центру → скобки соединяют пары → у пары появляются две карточки стихов.
- **P8 Ряд-счёт.** Предметный ряд точек (12 месяцев, 19 стихов) зажигается по одной с тиком.
- **P9 Световая развёртка.** Горизонтальная светящаяся линия проходит панель сверху вниз,
  «считывая» данные; используется как переход между состояниями панели.
- **P10 Финальная карточка.** Логотип канала проявляется из точек данных последней сцены,
  под ним строка методики.

## 6. Объекты и ассеты

- Только данные (точки, полосы, оси, кольца), типографика и свет. Никаких стоковых фото,
  иллюстраций, 3D-книг, людей.
- Шрифты локально: `assets/fonts/marcellus/`, `assets/fonts/spectral/`,
  `assets/fonts/amiri-quran/`, `assets/fonts/inter/` (все OFL; лицензии рядом).
- Логотип канала — только из `assets/logos/<channel>/`, не генерировать.
- Данные — `assets/data/quran/` (закреплённые файлы + `SOURCES.md` с sha256, §F1).

## 7. Переходы

- Базовый: панель/текст уходит в blur 8 px + прозрачность 0 за 0.6 с, следующая сцена
  входит из blur за 0.6 с, перекрытие 0.3 с. Мгновенных замен нет.
- Через данные: точки текущей сцены перелетают в форму следующей (P6, 1.2–2.0 с).
- Развёртка P9 — для смены состояния внутри панели.
- Нарратив меняется пословным проявлением (stagger 0.06 с на слово, fade + подъём 8 px),
  уходит целиком за 0.4 с. Арабский — только по I6.

## 8. Тайминг и чтение (формат без голоса)

- **Время задаёт чтение:** фраза нарратива держится `max(2.5, 1.0 + 0.30 × слов)` с после
  полного проявления; карточка стиха — `2.0 + 0.30 × слов перевода` с (не меньше 4.0 с).
- Между фразами пауза 0.3–0.5 с (пустой нарратив, данные продолжают жить).
- Внутри длинного плана событие не реже чем раз в 1.5 с (тик счётчика, вспышка, волна,
  развёртка). Статичный кадр без движения > 1.5 с запрещён (кроме финальной карточки, где
  идёт медленный световой дрейф).
- События звука привязаны к видимым событиям ±0.03 с.
- U10–U12 `production-qa` (голос ведёт, пословные тайминги) не применяются — их заменяет
  этот раздел. Остальные пункты части A действуют.

## 9. Параметры движения

| Элемент | Длительность | Easing | Прочее |
|---|---|---|---|
| Проявление сетки (P1) | 1.2–1.6 с | easeOutCubic | волна сверху вниз |
| Загорание точки (P2) | 0.25 с | easeOutExpo | всплеск 4–6 частиц, ≤ 0.4 с |
| Счётчик | синхронно с точками | linear по индексу | табличные цифры |
| «=» и волна (P3) | 0.4 с + волна 1.0 с | easeOutQuart | волна R 0→420 px, прозрачность 0.5→0 |
| Нарратив, слово | 0.45 с, stagger 0.06 | easeOutCubic | подъём 8 px |
| Арабский стих | 0.7 с | easeInOutSine | целиком, без частиц |
| Перестановка (P6) | 2.0–3.0 с | easeInOutCubic | motion blur ≤ 4 px |
| Развёртка (P9) | 1.0–1.4 с | linear | линия 2 px + glow 24 px |
| Камера | весь ролик | — | медленный наезд 1–2% за сцену, без панорам |

**Звук:** эмбиент-пад без вокала и ударных (−24…−20 dB), природа (птицы/сверчки) −30 dB
опционально; SFX: мягкий тик на загорание (не чаще 20/с, дальше — «шорох»), колокол на «=»,
воздушный «вжух» на переходах, низкий удар на ключевом числе. Песни и узнаваемые нашиды
не использовать. Источник и лицензия каждого файла — в `media/sources.md`.

## F. Факты — обязательный раздел

Цель: каждое число и каждая цитата в ролике воспроизводимы из закреплённых данных и
первоисточников, без участия человека-проверяющего.

**F1. Закреплённые данные.** До первого ролика в `assets/data/quran/SOURCES.md`: для каждого
файла — источник (URL), дата загрузки, версия, лицензия, sha256. Обязательные файлы:
арабский текст Tanzil Uthmani (хафс); морфология QAC v0.4 (или форк, §2); перевод Yusuf Ali
1934; метаданные сур (число стихов, мекканская/мединская по принятому стандарту, порядок
откровения). Данные из ответа модели, из памяти или с «агрегатора без источника» не
используются. Каждый ролик записывает sha256 использованных файлов в `media/facts.json`.

**F2. Сначала правило, потом подсчёт.** Для каждого счёта в `media/methods.md` до запуска
пишется: единица (слово / стих), критерий (лемма / корень / форма), фильтры (род, число,
часть речи), что включено и исключено и почему. После запуска правило не меняется, чтобы
«попасть» в известное число. Если известное число получается только при узком правиле —
правило показывается в кадре ярлыком («lemma ākhir · feminine forms», «singular only»).
Если не получается ни при каком естественном правиле — сцену убрать, а в отчёте написать
реальное число.

**F3. Каждое число — из скрипта.** Все числа на экране импортируются композицией из
`media/facts.json`, который генерирует `scripts/quran/count.py` (или другой скрипт в
`scripts/quran/`). Ручного ввода чисел в сценах нет (проверка: в коде сцен нет числовых
литералов в текстовых узлах, кроме дат оси из `facts.json`). Для каждого счёта сохраняется
CSV всех вхождений (`media/counts/<name>.csv`); точки на панели подсвечиваются ровно по нему.
Перед любым подсчётом — `count.py selftest` (должен быть `ok` по всем строкам).

**F4. Цитаты дословно и по ключу.** Арабский и перевод берутся из закреплённых файлов по
ключу `сура:аят` скриптом (`scripts/quran/quote.py`), а не перепечатываются. Скобки,
пунктуация и архаизмы Yusuf Ali сохраняются. Обрезка цитаты допустима только по границе
фразы и обозначается «…». Проверка: побайтовое сравнение текста сцены с файлом.
Подсвеченное слово в переводе должно соответствовать подсвеченному арабскому слову
(по таблице word-by-word QAC).

**F5. Хадисы.** Только Sahih al-Bukhari и Sahih Muslim. В `media/sources.md` для каждого:
сборник, номер **с указанием системы нумерации** (например, sunnah.com / Fath al-Bari),
арабский текст и английский перевод из двух независимых источников, ключевая фраза,
подтверждающая утверждение на экране. Утверждение в кадре не шире текста хадиса. Номер из
референса или из памяти без сверки не используется.

**F6. Исторические и научные утверждения.** Порядок откровения — названный стандарт
(например, порядок египетского издания 1924 г.), в кадре — «traditional order». Даты 610 /
622 / 632 CE — «traditional dates». Структурные схемы сур — только из рецензируемых работ
(автор, журнал, год, страницы) с подписью «ring structure: <author> (<year>)»; границы секций
берутся из работы, не придумываются. Любое «первое/последнее откровение» — с источником
(хадис F5 или классический тафсир с томом и страницей) и формулировкой «among the first /
among the last», если источники расходятся.

**F7. Язык утверждений.** Наблюдение, не доказательство: «appears 115 times», «placed side
by side», а не «miracle», «proof», «impossible by chance», «science confirms». Никаких
вероятностей «1 к N». Строка методики в финале: «Counts: <morphology dataset>, <text
edition>. Method: <короткое правило или ссылка>». Полная методика — в описании ролика
(генерируется из `methods.md`).

**F8. Автоматическая проверка (вместо человека).** Перед пилотом и перед рендером:
1. `count.py selftest` → все `ok`; sha256 файлов = `SOURCES.md`.
2. `verify_facts.py` пересчитывает каждый счёт из `methods.md` и сравнивает с `facts.json`.
3. **Второй независимый подсчёт** каждого ключевого числа другим способом (поиск по
   поверхностным формам в тексте Tanzil со списком форм из CSV). Расхождение → объяснить в
   `methods.md` или убрать сцену.
4. `quote.py --check` — все цитаты совпадают с файлами побайтово.
5. **Fact red-team:** отдельный субагент со свежим контекстом получает только сценарий и
   доступ к данным/источникам и для каждого утверждения выносит «подтверждено / не
   подтверждено / сформулировано шире источника». Любое «не» → правка или удаление.
6. Таблица `media/fact-sheet.md`: утверждение → тип (count/quote/hadith/history/scholar) →
   значение → источник → проверка 1–5 → статус. Рендер запрещён, пока есть строка не
   `verified`.
Если источник недоступен из среды агента — утверждение считается непроверенным (не
«по памяти»), сообщить пользователю.

## 10. Этапы и согласования

1. **Тема и тезисы** → `media/spec.md` (тема, скелет 4.2/4.3/4.4, 3–6 тезисов). Ок
   пользователя.
2. **Методика** → `media/methods.md` (§F2) — до подсчётов.
3. **Подсчёты и источники** → `media/facts.json`, `media/counts/*.csv`, `media/sources.md`,
   `media/fact-sheet.md`; проверки §F8 1–5. Показать пользователю fact-sheet (не
   спрашивая разрешения на каждый пункт — это отчёт).
4. **Сценарий-раскадровка** → `media/scene-plan.md`: сцена → текст на экране (дословно) →
   механика P.. → данные (ключ facts.json) → длительность по §8. Ок пользователя.
5. **Пилот (первый ролик формата обязательно):** 3 фрагмента — хук, P2+P3 (подсчёт и
   сравнение), один переход. Самопроверка §11. Ок пользователя → статус workflow
   «проверен пилотом».
6. **Полная сборка и рендер**, самопроверка §11, отчёт.

## 11. Режиссёрская самопроверка (по encoded MP4)

- Технически: ffprobe 1080×1920, 60 fps, h264+aac; длина 50–110 с; громкость −16…−14 LUFS.
- Факты: §F8 все пункты зелёные; числа в кадре (по кадрам покоя) = `facts.json`; количество
  горящих точек на кадре = числу на счётчике (I5); строка методики на финале.
- Визуально: контактные листы 2 к/с; кадр 360 px ширины; `layout-lint` = `[]` на кадре покоя
  каждой сцены; кадры 0 / 2.5 с / середина / последний с наложенной сеткой I4; фон I1 ±2;
  ни одного текста < 30 px; арабский не задет частицами (I6).
- Чтение: каждая фраза держится не меньше формулы §8 (таблица «фраза → слов → держится»);
  нет отрезка > 1.5 с без события.
- Звук: SFX только на видимые события; без вокала.
- Отчёт пользователю в трёх категориях: техническая / визуальная / факты (вместо речевой).

## 12. Технические уроки (сохранять)

- 10.10.2026: известные «равенства» воспроизводятся только при конкретных правилах:
  «ад-дунья 115» — лемма دُنْيا (115 вхождений в 111 стихах); «аль-ахира 115» — лемма آخِر
  **только женские формы** (все роды — 155); «шахр 12» — **только единственное число** (все
  формы — 21); Иса 25 / Адам 25 — по леммам; «قل 332 = قالوا 332» — лемма قالَ, повелительное 2MS против перфекта 3MP. Всё это проверено `count.py selftest` на форке
  QAC (sha256 742bfac5…). Правила обязаны быть в кадре (F2).
- Фильтр рода «F» не должен совпадать с тегом FUT (будущее время) — в `count.py` род/число
  сравниваются по компонентам.
- Частицы рендерить с фиксированным seed; иначе кадры превью и финала расходятся.
